## Rebuild and verify

From the project root, after completing the relevant [browser acceptance checks](../development.md#dedicated-browser-validation):

```sh
node --test tests/*.test.cjs
node tests/check.mjs
python3 scripts/package.py
(cd artifacts/release && shasum -a 256 -c SHA256SUMS)
```

The packager reads the manifest version, places `manifest.json` at the archive root, includes MIT `LICENSE`, and verifies CRC, inventory and source-file hashes. It rejects unknown runtime files and symlinks, excluding generated metadata, artwork, tests, documentation and browser/account data. Its allowlist is authoritative. Fixed ZIP order, permissions and timestamps make output reproducible in the same environment; zlib differences may change compressed bytes. Packaging integrity does not establish network safety.

For optional image regeneration, follow [artwork preparation](../../assets/README.md#store-exports). Pre-generated images are available; artwork tooling is not a runtime requirement.

## Where to set up your Chrome Web Store account

The account owner must complete these steps in the official [Developer Dashboard](https://chrome.google.com/webstore/devconsole/):

1. Select the owning Google account, register, accept the agreement/policies and pay the one-time developer fee. The extension remains free. Changing the account email may require a new account/item transfer.
2. Set the public publisher name (draft: `wtchangdm`), verify the contact email and enable [Google 2-Step Verification](https://myaccount.google.com/security).
3. Declare Trader/Non-Trader status and complete applicable verification. This legal classification cannot be inferred from GitHub or free pricing; verified legal/contact details may be public.

Contact-email verification is reported complete by the user, not independently inspected. Registration/payment, 2-Step Verification, final publisher name and Trader status remain unconfirmed. Credentials, payment details, identity documents, personal addresses and verification codes belong only in Google's account flow, not this repository or chat.

Official guidance: [registration](https://developer.chrome.com/docs/webstore/register), [account setup](https://developer.chrome.com/docs/webstore/set-up-account), [Trader verification](https://developer.chrome.com/docs/webstore/program-policies/trader-verification-faq).

- [ ] Obtain explicit upload/submission authorization, then separate publication authorization. Preparation alone authorizes neither.

## Store requirements and submission

Recheck [listing fields](https://developer.chrome.com/docs/webstore/cws-dashboard-listing), [image requirements](https://developer.chrome.com/docs/webstore/images) and live dashboard wording before submission. The short description limit is 132 characters. Required images are a 128×128 PNG icon, 440×280 small promo and one to five screenshots at 1280×800 or 640×400. A 1400×560 marquee and promotional video are optional; a screenshot is not a marquee.

Once authorized:

1. Upload the verified package to the existing item, or use **Items → Add new item** only for a first listing. Fill Listing, Privacy, Distribution and Test instructions from the prepared materials; use the confirmed distribution settings above.
2. Resolve warnings and obtain **Submit for Review** authorization. Use deferred publishing rather than automatic publication. The [publishing guide](https://developer.chrome.com/docs/webstore/publish) describes a 30-day staged-publication window after review; recheck it before submission.
3. After approval, obtain separate publication authorization. A store-assigned extension ID differs from the unpacked ID; preferences do not automatically migrate between installations.

## Optional automation

No CI credentials are configured. Local packaging requires no public release. Store API automation needs an existing item ID, publisher ID and owner-managed Google Cloud/API authentication; never put tokens or secrets in the repository/chat. For a first item, an authorized dashboard draft upload supplies the item ID; complete Listing and Privacy fields there before publication.

API upload does not complete listing setup or authorize publication. API `publish` can submit for review and supports staging. After a dashboard visibility change, API publication remains unavailable until the item has been manually published with that visibility at least once. Use the manual first-release path, then automate updates with increasing versions if requested.

References: [API setup and visibility restrictions](https://developer.chrome.com/docs/webstore/using-api), [v2 upload](https://developer.chrome.com/docs/webstore/api/reference/rest/v2/media/upload), [v2 publish/staging](https://developer.chrome.com/docs/webstore/api/reference/rest/v2/publishers.items/publish), [support hub](https://developer.chrome.com/docs/webstore/support-users), [support policy](https://developer.chrome.com/docs/webstore/program-policies/policies), [developer agreement](https://developer.chrome.com/docs/webstore/program-policies/terms).
